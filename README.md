# Jawon

A local-first Android music player where the library is a **room**, not a list.

A wall of shelves holds CD jewel cases that levitate, turn, and glow in their own
lit bay. Tap one and it pulls out of its slot, turns to face you, opens, and lifts the
disc out to spin up into playback. Turn the spinning disc to scrub. When the record
finishes, the case closes itself and puts you back on the wall.

Nothing is pre-loaded, and nothing comes from a streaming service: the music is yours — on the
phone, on a server you run, or openly licensed from the Internet Archive. The album is the
atomic unit: there is no cross-album shuffle, no feed, and no account.

## State

**0.7.1 beta.** Runs on 15+ devices, from a Galaxy S25 Ultra down to a Redmi 9 and a
Galaxy Note 8. Distributed as a signed APK through a separate public repository, with an
in-app updater; not on Play yet. See `docs/release.md` §5 for what is still outstanding
before a store listing.

A second room shipped in 0.7.1: a **pocket player** with a working click wheel, where the
phone's whole display is the player's face, reached through a showroom that moves between
rooms. Vinyl (0.8) and cassette (0.9) are next, then Google Play at 1.0 — see
`docs/roadmap.md`.

## Built with

**Compose** for every 2D screen, **Filament via [SceneView]** for the room, **Media3 /
ExoPlayer** behind a `MediaSessionService`, **Room** and **Hilt**. No 3D or animation
dependency beyond SceneView, on purpose — Filament already covers bloom, depth of field,
ambient occlusion, fog, vignette, grading, shadows and custom materials.

Geometry is imported glTF, generated by the committed Blender script
`tools/models/build_models.py`. Four hand-written materials in `app/src/main/materials/` —
dust, fog, the neon sign and the pocket player's polished steel — compiled by hand with a
version-matched `matc`.

[SceneView]: https://github.com/SceneView/sceneview-android

## Building

```bash
./gradlew assembleDebug
```

`JAVA_HOME` must point at a JDK 17 or newer. On the development machine there is no system
JDK — the only Java is the runtime bundled with Android Studio:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

Release builds need `keystore.properties` at the repository root, which is gitignored and
absent from a fresh clone. Without it the release build still works and falls back to the
debug key, so a minified build can be installed and tested — see `docs/release.md` §1.

CI runs the unit tests **and** a full R8 release build on every push
(`.github/workflows/ci.yml`). That second job is not redundant: Filament's JNI resolves
Java fields *by name*, so an over-eager R8 rule does not fail to build — it fails to render,
at runtime, on a device.

## Privacy

Jawon collects nothing. No account, no analytics, no telemetry, and no server of its own.

Six things use the network, and none of them reaches the developer. Two happen in ordinary
use and each has its own switch: a cover-art lookup (MusicBrainz and the Cover Art Archive)
and a lyrics lookup ([LRCLIB]). Four happen only when you act: checking for an update,
setting up a music server of your own, browsing the record shop (the Internet Archive), and
identifying a CD you rip (MusicBrainz). [`docs/privacy.md`](docs/privacy.md) describes each
one exactly — it was written against the code and verified against the manifest, and if a
change would make a sentence in it untrue, the policy changes in the same commit.

[LRCLIB]: https://lrclib.net

## Working on it

- **One thing at a time, checked on a device between changes.** This was ignored once —
  nine commits, one check at the end — and the check found a bug the first time the feature
  was actually exercised.
- **Instrument before guessing.** One log line beats three screenshots, and deleting code to
  bisect beats reading it to theorise. Both are traps 14 and 18 for a reason.
- **Check the thermal state before believing any frame rate.** The same build measured 124fps
  cool and 88fps hot; a 22% "regression" was once recorded on exactly that mistake.
- **The pure files are where the logic goes.** Every package has tests because the values
  worth checking were moved out of the Android-coupled classes that computed them. When a
  change is hard to test, that is usually the finding.
